# Conectando um Projeto Flutter ao Supabase

## Objetivo do material

Neste material, você aprenderá a configurar um projeto Flutter para se conectar ao Supabase. O foco é preparar a conexão entre o aplicativo e o projeto remoto no Supabase, usando a biblioteca `supabase_flutter`, um arquivo centralizado de configuração e a inicialização correta no `main.dart`.

Ao final, o projeto deverá ser capaz de inicializar o Supabase e realizar uma consulta simples à tabela `tutors`, que já deve existir no banco remoto. O CRUD remoto da feature Tutor não será implementado aqui; esta etapa serve apenas para deixar a conexão pronta e validada. 

---

## 1. Contextualização: por que conectar o Flutter ao Supabase?

Em um aplicativo Flutter, os dados podem ser armazenados localmente, em arquivos, em SQLite ou em um serviço remoto. Quando o projeto precisa compartilhar dados entre dispositivos, permitir sincronização ou usar autenticação e banco de dados em nuvem, é necessário conectar o aplicativo a um backend remoto.

O Supabase cumpre esse papel oferecendo um banco PostgreSQL, APIs automáticas, autenticação e controle de acesso. No contexto do projeto Pet Care, a tabela `tutors` já foi criada no Supabase. Agora, o aplicativo Flutter precisa saber como encontrar esse projeto remoto e como se autenticar usando uma chave pública apropriada para aplicativos clientes.

A configuração envolve cinco etapas principais:

1. adicionar a dependência `supabase_flutter`;
2. localizar a URL do projeto e a chave pública no painel do Supabase;
3. criar um arquivo de configuração para centralizar esses dados;
4. inicializar o Supabase antes de executar o aplicativo;
5. testar se a conexão foi estabelecida corretamente.

## 2. Conceitos fundamentais

### Flutter

Flutter é o framework usado para construir o aplicativo. Ele executa o código Dart no dispositivo do usuário e precisa inicializar bibliotecas externas antes que o app comece a rodar, especialmente quando essas bibliotecas dependem de configuração assíncrona.

No caso do Supabase, a inicialização precisa ocorrer antes de `runApp`, porque o aplicativo deve estar preparado para usar o cliente Supabase quando suas telas, controllers ou repositórios forem carregados.

### Supabase

Supabase é a plataforma remota que armazenará dados da aplicação. Neste material, ele será usado como origem remota para a tabela `tutors`.

O aplicativo Flutter não acessa o banco diretamente como um cliente PostgreSQL tradicional. Ele usa a biblioteca do Supabase, que se comunica com os serviços do projeto remoto por meio da URL do projeto e de uma chave pública.

### Project URL

A `Project URL` identifica o endereço do projeto Supabase. Ela costuma ter este formato:

```text
https://xxxxxxxxxxxxx.supabase.co
```

Essa URL diz ao aplicativo para qual projeto Supabase ele deve enviar as requisições.

Se a URL estiver errada, incompleta ou pertencer a outro projeto, o aplicativo não conseguirá acessar corretamente os dados esperados.

### Publishable Key

A `Publishable Key` é uma chave pública usada pelo aplicativo cliente para acessar o Supabase conforme as permissões configuradas no projeto remoto.

Um exemplo de formato é:

```text
sb_publishable_xxxxxxxxxxxxxxxxxx
```

Essa chave pode ser usada no aplicativo Flutter porque ela é uma chave pública. Mesmo assim, ela não dá permissão ilimitada por si só. O acesso real aos dados depende das políticas e permissões configuradas no Supabase.

### Chave pública não é chave secreta

Um ponto essencial é não colocar chaves secretas, administrativas ou de serviço dentro do aplicativo Flutter.

Aplicativos Flutter rodam no dispositivo do usuário. Isso significa que qualquer chave embutida no app pode ser extraída por alguém com conhecimento técnico. Por isso, chaves administrativas devem ficar apenas em ambientes controlados, como servidores ou funções backend.

No aplicativo Flutter, use apenas a chave pública apropriada para clientes.

## 3. Adicionando a dependência do Supabase

O primeiro passo é adicionar a biblioteca `supabase_flutter` ao arquivo `pubspec.yaml`.

No projeto Pet Care, o arquivo já possui dependências como `path` e `sqlite`. A dependência do Supabase deve ser adicionada dentro da seção `dependencies`.

Exemplo:

```yaml
dependencies:
  flutter:
    sdk: flutter
  path: ^1.9.1
  sqlite: ^2.4.2+1
  supabase_flutter: ^2.10.0
```

A biblioteca `supabase_flutter` fornece os recursos necessários para inicializar o Supabase, criar um cliente de acesso e executar operações como consultas, inserções, atualizações e exclusões.

Depois de alterar o arquivo, execute no terminal:

```bash
flutter pub get
```

Esse comando baixa a dependência adicionada e atualiza o projeto para que a biblioteca possa ser importada no código Dart.

### Como validar esta etapa

A validação mais simples é executar:

```bash
flutter pub get
```

Se o comando terminar sem erro, a dependência foi reconhecida pelo Flutter. Caso apareça erro de indentação, versão incompatível ou dependência não encontrada, revise o `pubspec.yaml`.

Em arquivos YAML, a indentação é importante. Um espaço a mais ou a menos pode fazer o arquivo deixar de ser interpretado corretamente.

## 4. Obtendo os dados de conexão no Supabase

Para conectar o Flutter ao Supabase, você precisa localizar duas informações no painel do Supabase:

```text
Project URL
Publishable Key
```

O caminho indicado no material-base é:

```text
Abrir Configurações → Ir para API/Data → Copiar URL e Chave
```

A `Project URL` identifica o projeto remoto. A `Publishable Key` permite que o aplicativo cliente faça requisições conforme as permissões configuradas.

Esses dados devem ser copiados com atenção. Um erro em apenas um caractere pode impedir a conexão.

### Cuidados ao copiar as credenciais

A URL deve começar com:

```text
https://
```

E normalmente terminar com:

```text
.supabase.co
```

A chave pública deve ser copiada integralmente. Não altere, não quebre em várias linhas e não remova partes do texto.

Não use uma chave secreta no aplicativo. Se o painel mostrar diferentes tipos de chave, escolha a chave pública indicada para uso no cliente.

## 5. Criando o arquivo de configuração

Para evitar espalhar os dados de conexão por várias partes do projeto, crie um arquivo específico para armazenar a configuração do Supabase.

A estrutura sugerida é:

```text
lib/core/supabase/supabase_config.dart
```

Dentro desse arquivo, crie a classe `SupabaseConfig`:

```dart
class SupabaseConfig {
  static const String url = 'COLE_AQUI_A_PROJECT_URL';
  static const String publishableKey = 'COLE_AQUI_A_PUBLISHABLE_KEY';
}
```

Depois, substitua os valores de exemplo pelos dados reais copiados do painel do Supabase.

Exemplo estrutural:

```dart
class SupabaseConfig {
  static const String url = 'https://xxxxxxxxxxxxx.supabase.co';
  static const String publishableKey = 'sb_publishable_xxxxxxxxxxxxxxxxxx';
}
```

Os valores acima são apenas exemplos. Cada projeto Supabase possui sua própria URL e sua própria chave.

### Por que centralizar a configuração?

Centralizar a configuração melhora a manutenção. Se a URL ou a chave precisar ser alterada, você muda apenas um arquivo.

Sem essa centralização, os mesmos dados poderiam ser repetidos em várias classes, telas ou services. Isso aumenta o risco de inconsistência, dificulta a manutenção e torna o código mais propenso a erros.

### O que observar

Esse arquivo guarda informações necessárias para o aplicativo se conectar ao Supabase. Embora a chave pública possa estar no app, ela ainda deve ser tratada com cuidado. Não confunda chave pública com chave administrativa.

## 6. Atualizando o `main.dart`

O Supabase precisa ser inicializado antes da execução principal do aplicativo. Por isso, o método `main` deve ser assíncrono.

Antes da alteração, o `main.dart` pode estar assim:

```dart
void main() {
  WidgetsFlutterBinding.ensureInitialized();
  runApp(const MyApp());
}
```

Depois da alteração, ele deve inicializar o Supabase antes de chamar `runApp`:

```dart
Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();

  await Supabase.initialize(
    url: SupabaseConfig.url,
    anonKey: SupabaseConfig.publishableKey,
  );

  runApp(const MainApp());
}
```

### Por que o `main` precisa ser `async`?

A inicialização do Supabase pode envolver preparação interna da biblioteca e configuração do cliente. Como essa operação é assíncrona, usamos `await`.

Para usar `await`, a função precisa ser marcada como `async`.

Por isso, o método deixa de ser:

```dart
void main()
```

E passa a ser:

```dart
Future<void> main() async
```

### Por que chamar `WidgetsFlutterBinding.ensureInitialized()`?

Esse método garante que a infraestrutura do Flutter esteja pronta antes de executar inicializações que dependem dela.

Quando o aplicativo executa tarefas antes de `runApp`, especialmente tarefas assíncronas, é uma boa prática chamar:

```dart
WidgetsFlutterBinding.ensureInitialized();
```

Assim, o ambiente Flutter fica preparado antes da inicialização do Supabase.

### Diferença entre `publishableKey` e `anonKey`

No arquivo de configuração, o nome usado é:

```dart
publishableKey
```

Mas, ao chamar `Supabase.initialize`, o parâmetro da biblioteca continua sendo:

```dart
anonKey
```

Isso não é erro. O nome `publishableKey` foi escolhido no arquivo do projeto para deixar mais claro que a chave é pública. Já `anonKey` é o nome esperado pelo método da biblioteca `supabase_flutter`.

## 7. Estrutura completa do `main.dart`

O início do arquivo `main.dart` deve importar o Flutter, o Supabase e o arquivo de configuração criado.

Exemplo completo:

```dart
import 'package:flutter/material.dart';
import 'package:supabase_flutter/supabase_flutter.dart';

import './core/supabase/supabase_config.dart';
import './features/pet/presentation/pages/pet_list_page.dart';
import './features/tutor/presentation/pages/tutor_list_page.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();

  await Supabase.initialize(
    url: SupabaseConfig.url,
    anonKey: SupabaseConfig.publishableKey,
  );

  runApp(const MainApp());
}

class MainApp extends StatelessWidget {
  const MainApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Pet Care',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(
        useMaterial3: true,
        colorScheme: ColorScheme.fromSeed(
          seedColor: const Color(0xFF0F766E),
          primary: const Color(0xFF0F766E),
          secondary: const Color(0xFFF97316),
          surface: const Color(0xFFF8FAFC),
        ),
        appBarTheme: const AppBarTheme(
          backgroundColor: Colors.white,
          foregroundColor: Color(0xFF1E293B),
          elevation: 0,
        ),
        fontFamily: 'Inter',
      ),
      home: const TutorListPage(),
    );
  }
}
```

### Comentário do código

O import abaixo permite usar os componentes visuais e estruturais do Flutter:

```dart
import 'package:flutter/material.dart';
```

O import abaixo permite inicializar e acessar o Supabase:

```dart
import 'package:supabase_flutter/supabase_flutter.dart';
```

O import abaixo traz a classe que centraliza a URL e a chave pública:

```dart
import './core/supabase/supabase_config.dart';
```

A chamada abaixo inicializa o Supabase:

```dart
await Supabase.initialize(
  url: SupabaseConfig.url,
  anonKey: SupabaseConfig.publishableKey,
);
```

A chamada abaixo inicia o aplicativo depois que o Supabase já foi configurado:

```dart
runApp(const MainApp());
```

Essa ordem é importante. Se `runApp` for executado antes da inicialização, alguma parte do aplicativo pode tentar acessar o Supabase antes de ele estar pronto.

## 8. Testando a conexão com o Supabase

Antes de implementar a camada remota da feature Tutor, é importante fazer testes simples para confirmar que a configuração funciona.

Esses testes devem ser temporários. Eles servem para validar a conexão, não para substituir a implementação correta da camada de dados.

### Teste 1: verificar a inicialização

Adicione temporariamente um `debugPrint` logo após a inicialização:

```dart
await Supabase.initialize(
  url: SupabaseConfig.url,
  anonKey: SupabaseConfig.publishableKey,
);

debugPrint('Supabase inicializado com sucesso.');
```

Depois, execute o projeto:

```bash
flutter run
```

Se o aplicativo abrir normalmente e a mensagem aparecer no console, a inicialização foi executada.

### Resultado esperado

O console deve exibir:

```text
Supabase inicializado com sucesso.
```

Esse teste confirma que o código chegou até o ponto posterior à inicialização. Ele não confirma, sozinho, que a tabela `tutors` está acessível. Para isso, é necessário realizar uma consulta.

### Teste 2: realizar uma consulta simples

Para verificar se o aplicativo consegue consultar a tabela `tutors`, faça uma consulta limitada a um registro:

```dart
final response = await Supabase.instance.client
    .from('tutors')
    .select()
    .limit(1);

debugPrint('Teste: $response');
```

### Comentário do código

O trecho abaixo acessa o cliente Supabase já inicializado:

```dart
Supabase.instance.client
```

O trecho abaixo informa qual tabela será consultada:

```dart
.from('tutors')
```

O trecho abaixo solicita os dados:

```dart
.select()
```

O trecho abaixo limita o retorno a apenas um registro:

```dart
.limit(1)
```

Isso evita trazer muitos dados desnecessariamente durante o teste.

### Resultado esperado

Se a tabela existir e o acesso estiver permitido, o console deve mostrar uma resposta contendo uma lista. Essa lista pode vir vazia se a tabela ainda não tiver registros, mas a consulta não deve falhar.

Exemplo de retorno vazio:

```text
Teste: []
```

Exemplo de retorno com um registro:

```text
Teste: [{id: ..., name: ...}]
```

O formato exato depende dos campos existentes na tabela `tutors`.

Depois de validar a conexão, remova os trechos temporários do `main.dart`.

## 9. Aplicação prática resolvida: preparando e validando a conexão

### Cenário

O projeto Pet Care já possui uma tabela chamada `tutors` criada no Supabase. O aplicativo Flutter ainda não sabe como se conectar ao projeto remoto.

### Objetivo

Configurar o Flutter para inicializar o Supabase e executar uma consulta simples à tabela `tutors`.

### Solução

Primeiro, adicione a dependência no `pubspec.yaml`:

```yaml
dependencies:
  flutter:
    sdk: flutter
  path: ^1.9.1
  sqlite: ^2.4.2+1
  supabase_flutter: ^2.10.0
```

Depois, execute:

```bash
flutter pub get
```

Em seguida, crie o arquivo:

```text
lib/core/supabase/supabase_config.dart
```

Com o conteúdo:

```dart
class SupabaseConfig {
  static const String url = 'COLE_AQUI_A_PROJECT_URL';
  static const String publishableKey = 'COLE_AQUI_A_PUBLISHABLE_KEY';
}
```

Substitua os valores pelos dados reais do Supabase.

Depois, atualize o `main.dart`:

```dart
import 'package:flutter/material.dart';
import 'package:supabase_flutter/supabase_flutter.dart';

import './core/supabase/supabase_config.dart';
import './features/tutor/presentation/pages/tutor_list_page.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();

  await Supabase.initialize(
    url: SupabaseConfig.url,
    anonKey: SupabaseConfig.publishableKey,
  );

  final response = await Supabase.instance.client
      .from('tutors')
      .select()
      .limit(1);

  debugPrint('Teste de conexão com tutors: $response');

  runApp(const MainApp());
}

class MainApp extends StatelessWidget {
  const MainApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Pet Care',
      debugShowCheckedModeBanner: false,
      home: const TutorListPage(),
    );
  }
}
```

### Comentário da solução

A configuração é feita antes de `runApp`, garantindo que o cliente Supabase esteja pronto antes da interface ser carregada.

A consulta à tabela `tutors` é temporária. Ela aparece no `main.dart` apenas para validar se a conexão está funcionando. Em uma implementação final, essa consulta não deve ficar no `main.dart`.

### Resultado esperado

Ao executar:

```bash
flutter run
```

O aplicativo deve abrir normalmente, e o console deve exibir algo parecido com:

```text
Teste de conexão com tutors: []
```

Ou uma lista com dados, se a tabela tiver registros.

### Como validar

A conexão está validada quando:

* `flutter pub get` executa sem erro;
* o app inicia sem falhar na chamada `Supabase.initialize`;
* a consulta à tabela `tutors` retorna uma resposta no console;
* a resposta é uma lista vazia ou uma lista com registros;
* não há erro de URL, chave, tabela inexistente ou permissão.

### Possíveis erros nesta prática

Se o app falhar antes de abrir, revise a inicialização no `main.dart`.

Se o erro mencionar URL inválida, revise a `Project URL`.

Se o erro mencionar autenticação, revise a `Publishable Key`.

Se o erro mencionar relação ou tabela inexistente, confirme se a tabela `tutors` foi criada.

Se o erro mencionar permissão, o problema provavelmente está relacionado às regras de acesso configuradas no Supabase.

Depois do teste, remova a consulta temporária do `main.dart`.

## 10. Possíveis erros e como resolver

### Erro na URL

Esse erro acontece quando a URL do Supabase foi copiada incorretamente ou está incompleta.

Verifique se a URL:

```text
começa com https://
termina com .supabase.co
pertence ao projeto correto
não possui espaços antes ou depois
```

Se a URL estiver incorreta, o aplicativo não conseguirá localizar o projeto Supabase.

### Chave pública incorreta

Esse erro acontece quando a chave pública foi copiada incompleta, alterada ou retirada do local errado no painel.

Para resolver, volte ao painel do Supabase, copie novamente a `Publishable Key` e substitua o valor no arquivo:

```text
lib/core/supabase/supabase_config.dart
```

Não use chave secreta no lugar da chave pública.

### Tabela inexistente

Se a tabela `tutors` não existir, a consulta falhará. Nesse caso, confirme se a tabela foi criada corretamente no Supabase.

Também verifique se o nome foi escrito corretamente. Em bancos de dados, `tutors`, `Tutor` e `tutor` podem não ser tratados da mesma forma dependendo do contexto.

No código, a consulta usa:

```dart
.from('tutors')
```

Portanto, a tabela esperada se chama exatamente:

```text
tutors
```

### Permissão de acesso bloqueada

A tabela pode existir, a URL pode estar correta e a chave pública também, mas a consulta ainda pode falhar por causa das regras de segurança.

Nesse caso, o problema não está necessariamente no Flutter. Pode estar nas políticas de acesso configuradas no Supabase.

As regras de segurança definem quem pode consultar, inserir, alterar ou excluir dados. Esse tema deve ser tratado com cuidado, porque permissões abertas demais podem expor dados indevidamente, enquanto permissões restritas demais podem bloquear o funcionamento do aplicativo.

### Erro de importação

Se o Dart não reconhecer `Supabase`, verifique se o import foi adicionado:

```dart
import 'package:supabase_flutter/supabase_flutter.dart';
```

Se o Dart não reconhecer `SupabaseConfig`, verifique se o caminho do arquivo está correto:

```dart
import './core/supabase/supabase_config.dart';
```

Também confirme se o arquivo realmente existe no caminho:

```text
lib/core/supabase/supabase_config.dart
```

### Erro por esquecer `await`

Se a inicialização for chamada sem `await`, o app pode continuar a execução antes de o Supabase estar pronto.

O correto é:

```dart
await Supabase.initialize(
  url: SupabaseConfig.url,
  anonKey: SupabaseConfig.publishableKey,
);
```

E o método `main` deve ser:

```dart
Future<void> main() async
```

## 11. Por que não consultar o Supabase diretamente nas telas?

Mesmo que a consulta de teste funcione no `main.dart`, isso não significa que as telas devam acessar o Supabase diretamente.

O teste no `main.dart` serve apenas para confirmar que a conexão foi configurada corretamente. A implementação definitiva deve respeitar a organização em camadas do projeto.

A estrutura esperada é:

```text
TutorListPage
Camada de apresentação: exibe os dados ao usuário.

TutorController
Camada de controle: gerencia estado e lógica de negócio.

TutorRepository
Camada de repositório: abstrai a origem dos dados.

TutorRemoteDataSource
Camada de dados remotos: conversa diretamente com o Supabase.
```

A responsabilidade de conversar com o Supabase deve ficar na camada de dados remotos. Isso mantém o projeto mais organizado, testável e fácil de manter.

### Problema de consultar diretamente na tela

Se uma tela chama o Supabase diretamente, ela passa a acumular responsabilidades demais. Ela deixa de apenas exibir dados e passa também a conhecer detalhes de infraestrutura, consulta remota e origem dos dados.

Isso dificulta mudanças futuras. Por exemplo, se a origem dos dados mudar, várias telas podem precisar ser alteradas.

### Benefício da separação em camadas

Com uma estrutura em camadas, a tela não precisa saber se os dados vêm do Supabase, de SQLite, de cache local ou de outra fonte.

A tela solicita dados ao controller. O controller usa o repositório. O repositório decide a origem. O data source remoto executa a comunicação com o Supabase.

Essa organização reduz acoplamento e melhora a manutenção.

## 12. Checklist explicado de validação

### A dependência `supabase_flutter` foi adicionada ao `pubspec.yaml`

Verifique se a linha abaixo está dentro de `dependencies`:

```yaml
supabase_flutter: ^2.10.0
```

Isso importa a biblioteca necessária para inicializar e usar o Supabase no Flutter.

Para validar, execute:

```bash
flutter pub get
```

Se essa etapa faltar, o projeto não reconhecerá os imports e classes do Supabase.

### O arquivo de configuração foi criado no caminho correto

Verifique se existe o arquivo:

```text
lib/core/supabase/supabase_config.dart
```

Esse arquivo centraliza a URL e a chave pública do Supabase.

Para validar, importe o arquivo no `main.dart`:

```dart
import './core/supabase/supabase_config.dart';
```

Se o caminho estiver incorreto, o Dart mostrará erro de importação.

### A URL do projeto foi copiada corretamente

Verifique se `SupabaseConfig.url` contém a URL completa do projeto Supabase.

Ela deve seguir o formato:

```text
https://xxxxxxxxxxxxx.supabase.co
```

A URL é essencial porque identifica o projeto remoto. Se ela estiver errada, o aplicativo tentará acessar um endereço inválido ou outro projeto.

### A chave pública foi copiada corretamente

Verifique se `SupabaseConfig.publishableKey` contém a chave pública correta.

Ela deve ser uma chave própria para uso no cliente, não uma chave secreta administrativa.

Se essa etapa faltar ou estiver incorreta, as requisições ao Supabase poderão falhar por autenticação ou permissão.

### O método `main` foi transformado em assíncrono

Verifique se o método principal está assim:

```dart
Future<void> main() async
```

Isso é necessário porque a inicialização do Supabase usa `await`.

Se o `main` continuar como `void main()`, o código não poderá usar `await` corretamente.

### `WidgetsFlutterBinding.ensureInitialized()` foi chamado antes da inicialização

Verifique se o início do `main` contém:

```dart
WidgetsFlutterBinding.ensureInitialized();
```

Isso prepara o ambiente Flutter antes de executar inicializações assíncronas.

Se essa etapa faltar, o aplicativo pode apresentar problemas ao executar configurações antes de `runApp`.

### O Supabase foi inicializado antes de `runApp`

Verifique se a chamada abaixo aparece antes de `runApp`:

```dart
await Supabase.initialize(
  url: SupabaseConfig.url,
  anonKey: SupabaseConfig.publishableKey,
);
```

Isso garante que o cliente Supabase esteja pronto antes da interface iniciar.

Se essa etapa faltar, telas, controllers ou repositórios podem tentar acessar o Supabase antes da configuração.

### A tabela `tutors` foi consultada apenas como teste temporário

Verifique se a consulta temporária foi usada somente para validar a conexão:

```dart
final response = await Supabase.instance.client

    .select()
```

Essa consulta não deve permanecer como implementação definitiva no `main.dart`.

Se ela ficar no `main.dart`, o arquivo principal passará a ter responsabilidade de acesso a dados, o que prejudica a organização do projeto.

### Os testes temporários foram removidos depois da validação

Depois de confirmar que o app inicializa e consulta a tabela, remova os `debugPrint` e consultas temporárias.

Isso mantém o `main.dart` limpo e evita que código de teste seja confundido com código de produção.
